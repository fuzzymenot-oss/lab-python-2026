## variant.py — книжный магазин

Только последовательные команды. Скидка не вводилась.

Формулы:

- стоимость позиции = количество × цена
- стоимость товаров = стоимость учебников + стоимость сборников
- итого с доставкой = товары + доставка
- общее количество = сумма количеств
- сдача = внесено − итого

Денежные значения печатаются с двумя знаками после точки в формате `название | количество | цена | стоимость`.

### Собственный пример (рассчитан вручную до запуска)

Заказ «Учебники к сессии», заказчик Иван Жуковский.

- учебник «Алгебра. 10 класс» — 2 шт. по 750.00 руб. → 1500.00
- сборник задач по физике — 1 шт. по 480.50 руб. → 480.50
- товары: 1500.00 + 480.50 = 1980.50
- доставка: 249.50
- итого: 1980.50 + 249.50 = 2230.00
- внесено: 2500.00
- сдача: 2500.00 − 2230.00 = 270.00
- единиц: 2 + 1 = 3

После запуска программа выдала те же числа.

Контрольный расчёт из задания: 3 × 12.50 и 2 × 20.00, доставка 10.00, внесено 100.00 → стоимости 37.50 и 40.00, товары 77.50, всего 87.50, количество 5, сдача 12.50.

## Что нужно уметь объяснить

**Строка и число.** `input()` всегда возвращает текст. `"17" + 1` невозможно: это разные типы. Для расчёта возраста или суммы сначала `int()` или `float()`, и только потом арифметика. `"2" + "3"` склеивает символы в `"23"`, а `int("2") + int("3")` даёт `5`.

**Порядок вычислений.** Сначала `*` и `/`, потом `+` и `-`. Поэтому `4 + 7 + 10 / 3` — это `4 + 7 + 3.333...`, а не среднее. Скобки `(4 + 7 + 10) / 3` меняют порядок и дают `7.0`. Делитель не должен быть равен нулю; в нагрузке деление на 60 безопасно, в карточке деление на 7 тоже.

**Временная переменная.** Чтобы поменять `first_room` и `second_room`, одно значение нужно куда-то сохранить. `temporary_room = first_room` копирует первое имя, затем первое поле затирается вторым, а во второе записывается сохранённая копия. Без третьей переменной одно из имён потерялось бы.

**Деньги.** Формат `{value:.2f}` всегда печатает два знака после точки: `12.5` становится `12.50`, `87.5` — `87.50`. Так проще читать чек.
